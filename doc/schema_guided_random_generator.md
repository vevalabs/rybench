# Schema-Guided Random Generator

`SchemaGuidedRandomGenerator` walks a `SchemaDefinition` field tree and produces
one random-but-valid message per `generate()` call. Every field gets a random
value of the correct type, honouring any constraints declared as `.fbs`
attributes. The generator decides *values* only; the serializer backend owns the
wire encoding.

Source: `src/rybench/generator/schema_guided/schema_guided_random_generator.{hpp,cpp}`

## Per-type generation rules

| Field type | How it is generated | Default range (no attribute) |
|------------|---------------------|------------------------------|
| `bool` | uniform 0/1 | — |
| `byte` `short` `int` `long` (signed) | uniform integer in `[min, max]` | `[-1000, 1000]` |
| `ubyte` `ushort` `uint` `ulong` (unsigned) | uniform integer in `[min, max]`, clamped `≥ 0` | `[0, 1000]` |
| `float` | uniform real in `[min, max]`, cast to float | `[-100, 100]` |
| `double` | uniform real in `[min, max]` | `[-100, 100]` |
| `string` | random chars, length in `[min_length, max_length]` | length `[3, 12]`, charset `[A-Za-z0-9]` |
| `enum` | uniform pick of a declared enum value | `0` if the enum has no values |
| vector `[T]` | random length in `[min_items, max_items]`, then each element generated by type | length `[1, 5]` |
| table / struct | recurse into child fields | — |

## Constraint attributes

Declared in the `.fbs` and read once at schema load into `FieldConstraints`:

| Attribute | Applies to | Effect |
|-----------|-----------|--------|
| `min` / `max` | numeric (int, uint, float, double) | inclusive value bounds |
| `min_length` / `max_length` | string | inclusive length bounds |
| `pattern` | string | restricts the character set (see below) |
| `min_items` / `max_items` | vector | inclusive element-count bounds |

### String patterns

`pattern` is matched against a small set of known character classes (not a full
regex engine):

| Pattern contains | Charset used |
|------------------|--------------|
| `[A-Z]` | `A–Z` |
| `[a-z]` | `a–z` |
| `[0-9]` | `0–9` |
| `[A-Za-z]` | `A–Z a–z` |
| anything else | `A–Z a–z 0–9` |

Example:
```
label:string (min_length: "4", max_length: "8", pattern: "^[A-Z]+$");
```
produces an uppercase string of length 4–8.

## Field roles (`generate` attribute)

Some fields are not random — they carry a *semantic role*, declared with the
`generate` attribute and resolved once at parse time into `core::FieldRole`
(`include/rybench/core/schema.hpp`). The generator hot path is a single
predicted branch, so ordinary fields pay no cost.

| `generate` value | Field role | Value produced |
|------------------|-----------|----------------|
| `"timestamp"` | `Timestamp` | current wall-clock, ms since epoch, at `generate()` time |
| `"counter"` | `Counter` | monotonically increasing per-field counter `0,1,2,…` (resets on `loadSchema()`) |
| *(absent)* | `None` | ordinary random value (rules above) |

Example:
```
attribute "generate";
table Packet {
  seq:ulong       (generate: "counter");    // 0,1,2,...
  timestamp:ulong (generate: "timestamp");  // wall-clock ms
  payload:uint;                             // random
}
```

> Note: a `timestamp` here is stamped at *generation* time, which is an
> approximation of send time. For precise IPC latency, stamp as close to
> `publish()` as possible in the transport.

## Test coverage

`tests/schema_guided_random_generator/` (GoogleTest, run via `ctest`). Each test
generates messages and reads the values back from the encoded FlatBuffer via
reflection, so it exercises the full generate → encode path.

| Test | Verifies |
|------|----------|
| `ParserAssignsRolesFromAttribute` | `generate` attr → `Counter` / `Timestamp` / `None` |
| `CounterIncrementsPerMessage` | counter = 0,1,2,… per message |
| `TimestampIsWallClockAndMonotonic` | timestamp is real ms, non-decreasing, not in the future |
| `CounterResetsOnReload` | `loadSchema()` resets counters |
| `OrdinaryFieldRespectsConstraint` | `int` ≤ `max` |
| `DoubleRespectsRange` | `double` in `[min, max]` |
| `FloatRespectsRange` | `float` in `[min, max]` |
| `StringRespectsLengthAndPattern` | length bounds **and** `^[A-Z]+$` |
| `StringWithoutPatternRespectsLength` | length bounds, alphanumeric |
| `EnumProducesValidValue` | only schema-declared enum values |
| `VectorRespectsItemBounds` | vector size in `[min_items, max_items]` |
| `NestedTableFieldRespectsConstraint` | recursion into a nested table; child field bounded |
| `BoolIsZeroOrOne` | `bool` ∈ {0, 1} |
| `SignedIntegerWidthsRespectRange` | `byte` / `short` / `long` within bounds |
| `UnsignedIntegerWidthsRespectRange` | `uint` / `ulong` within bounds |
| `UnboundedUnsignedIsNonNegative` | unsigned field with no bounds stays `≥ 0` |

Fixture schema: `tests/schema_guided_random_generator/fixtures/roles.fbs`.

Run:
```bash
ctest --test-dir build_release
```
